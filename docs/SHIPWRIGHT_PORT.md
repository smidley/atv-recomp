# Shipwright: first native game

**Target confirmed 2026-10-28:** run the [Shipwright entry](https://recomplauncher.com/game/shipwright)
on Apple TV using a ROM supplied by the user. Shipwright is **Ship of Harkinian**,
the native Ocarina of Time port. The sequence is Shipwright first, expand N64
coverage toward the full library, then other platforms. Development remains
simulator-only until physical-device testing is resumed.

## Native execution and the launcher

Shipwright compiles game source from the Ocarina of Time decompilation. It uses
libultraship for platform services and graphics, and extracts the user's ROM
assets into an O2R archive. The ROM is game data for this native port, not an
Apple TV executable. This differs from the earlier Zelda64Recomp investigation,
which uses N64Recomp-generated code and the RT64 renderer.

The launcher should offer one flow: acquire ROM, identify its exact revision,
select an included native runtime, prepare its assets, and play. A source port
and a static recompilation project can both fit that boundary. Each still needs
a tvOS integration and testing; the app cannot infer a working native runtime
from arbitrary ROM bytes. N64 coverage grows title by title, potentially sharing
platform services, without assuming one game's renderer fits all games.

## Local ROM identification prototype

With Python 3.9 or newer, from the repository root:

```sh
python3 scripts/identify-shipwright-rom.py /path/to/your/rom.z64
python3 experiments/shipwright/ROMIdentificationTests.py
```

The tool makes no network requests, writes no ROM or extracted assets, and uses
bounded chunks rather than reading the whole file into memory. It:

- Requires an uncompressed N64 header and complete four-byte words.
- Detects `.z64`, `.v64`, or `.n64` byte order from bytes, regardless of filename.
- Hashes canonical big-endian bytes against the exact 19-entry
  [upstream SHA-1 reference](https://github.com/HarbourMasters/Shipwright/blob/f0599f96f8d442f26d0fa1c5cedafddacd56633f/docs/supportedHashes.json).
- Also reports canonical SHA-256 and rejects an input that changes during reading.
- Reports `recognized` or `unsupported_revision`; it always reports
  `launchable: false` because no Shipwright runtime is integrated yet.

Exit codes are **0** for an upstream hash match, **1** for an unrecognized
revision, and **2** for malformed/unreadable input or an invalid reference file.
A reference match is byte identity, not a claim about ownership or gameplay.

The vendored hash list is copied verbatim, with its source commit and file SHA-256
recorded in the baseline. Tests use generated bytes and a separate fixture-only
allowlist to exercise successful matching. The real CLI always uses the pinned
upstream list. No real game ROM has been tested, uploaded, or included in CI.
These checks validate the host prototype; the app's validator still needs an
implementation and tests before any in-app import is advertised.

## Next simulator work

1. Audit and pin transitive libultraship/Torch dependencies; separate desktop
   window/dialog code and host asset tools from the tvOS build.
2. Compile libultraship's relevant services and Metal backend for tvOS Simulator.
   Exercise a bounded rendering fixture before adding the game loop.
3. Integrate game code with explicit input, audio, storage, lifecycle, and return
   to launcher boundaries. Validate asset extraction and boot with the user's ROM.
4. Prove repeatable launch/exit, save/reload, and controller-driven gameplay.
   Keep physical Apple TV compatibility and performance as deferred checks.
5. Add more N64 runtimes through the same registry, validation, asset preparation,
   and launch boundary. Investigate other platforms after the N64 phase.

Host extraction can simplify the first development boot. The intended product
still accepts a ROM and prepares required data through the launcher; it must not
require users to build games or manually assemble O2R archives.

## Prior experiment evidence

[PR #3](https://github.com/smidley/atv-recomp/pull/3) merged on 2026-10-28 after
its checks passed at `a5e5525`. Its
[RT64 workflow](https://github.com/smidley/atv-recomp/actions/runs/40749764962)
compiled and linked the isolated backend for both simulator architectures and
compiled three upstream shaders. Those results remain useful research, but do
not prove Shipwright builds, renders, or runs. The main app is still the foundation
harness, with no game runtime linked.
